# B-2 — Missions: per-stage tasks auto-verified by real sim state

**For agentic workers:** read `AGENTS.md`, `FACTORY.md`, `DESIGN.md` first; execute Step 2 mechanically with `npm run verify` green at every commit. Human sign-off 2026-10-26 (name "Missions"; control-room register per DESIGN.md amendment).

## Hard rules

- **NEVER** weaken a guardrail, test, threshold, or manifest rule. Zero runtime deps; no inline handlers/styles (CSP); strict `CHECKS:`/`PINS:`/`DOCUMENTS:` vocabulary.
- **File size:** js/css ≤ 300 (`panel.js` 299, `teaching.js` 175, `render.js` ~254 — new modules, not padding; `css/panel/teaching.css` 72 has room), tests ≤ 450 (`e2e/panel.spec.js` sits at 450 — touch it NOT), `panel.html` 546/550 → the missions section is JS-built into the existing drawer; NO template markup added there.
- **Same-change manifests:** `slices.yaml` + `storymap.yaml` with the feature.
- **Snapshots only (DL-1/DL-4):** `detect(snapshot)` predicates read real engine state fields; no RNG, no clock, no event listening to infer state.

## Branch contracts (DL-3/DL-4) — with named counter-examples

- **The sim is the referee.** Completion flips ONLY by a detector on the real snapshot. Named counter-examples, both PINNED in the unit suite: (1) a `405` response does NOT complete the stage-1 404 mission — a wrong-path mission checks `status === 404`, not non-2xx; (2) an origin cache HIT does NOT complete the stage-6 edge-HIT mission — the predicate reads the trace's edge status, `trace.edgeStatus === 'HIT'`, not `cacheStatus`.
- **Session-only memory.** A verified mission's done state, its completing tick, and progress text reset when defining: stage switch clears the whole verified set; a page reload starts empty. REMEMBER: verification survives any number of crowd ticks mid-session (a verified mission does not un-verify while the clock runs).
- **Pre-fill is input-only.** Clicking a mission that carries `url` fills `#url-input` (and nothing else). Counter-example: no `dispatch`/`click()` of `btn-url-go` — the learner presses the button; a click handler that auto-sends is a defect.
- **Cheap on every snapshot.** `updateView` runs per crowd tick and per hop; the detector pass must be pure field reads (no DOM writes when nothing changed — same-row stability).

## Pre-decided boundary contracts

### 1. `js/panel/missions.js` (new, DOM-free, unit-tested)

- Registry `MISSIONS: { <stageId>: [{ id, goal, url?, detect(snapshot) → boolean, progress(snapshot) → string }] }`, 2–3 missions per shipped stage (1–6). Ground every `detect`/`progress` field path in the real sim/panel snapshot shapes (`js/panel/model.js` `describeSnapshot`, engine snapshot — cache perBackend counters, db replica lag, worker queue state, trace edge/path fields, cdn ledger, dns stats). Goals derive from each stage's `try`/`watchFor` copy in `teaching.js` (the drawer narrative stays untouched).
- Pinned pair: stage-1 404 mission (goal "Get a 404 for a missing path"; `url: '/missing'`), stage-6 edge-HIT mission (goal "Serve an edge HIT at the CDN"; `url: 'cd.example.com/about'` after a MISS run exists in-session — the session shape is the e2e's job; the DETECTOR only sees snapshots).
- Pure status helper for the DOM module: `missionStatuses(stage, snapshot, verified)` → per-mission `{ done, completedTick, progress }` — no DOM.
- Validation: unknown stage → empty list (no throw; the drawer just renders nothing).

### 2. `js/panel/missions-view.js` (new, DOM-bound; covered by e2e)

- Mounts the `MISSIONS` section inside the teaching drawer aside (injection precedent: `compare.js` tray); list rebuilt on stage switch; `data-testid` set: `missions-section`, `mission-item`, `mission-status`.
- Per snapshot update: statuses flip `○ <progress>` → `✓ done · tick <N>`; mission click → `#url-input` value fill when `url` present.
- Exposes `updateMissions(snapshot)` and `resetMissions()` for panel.js: call the former from `updateView`, the latter from `switchStage`. Watch the panel.js 300-cap: if the touchpoints do not fit, move the update hook wiring (subscribing via an existing state/render hook used for the tray, if one exists) into missions-view and REPORT it.

### 3. Tests & manifests

- NEW `test/panel/missions.test.js`: per-stage detector pins incl. BOTH counter-examples above; cleared-on-stage-switch pin (pure state: verify → reset → not-done, completedTick forgotten); progress-text pin (pending mission with a progress string derived from the same snapshot field its detector reads — e.g. edge-mission pending shows `fills: n`).
- NEW `e2e/missions.spec.js`: `should verify a mission automatically from real sim state (stage 1: 404)`; `should not complete the 404 mission on a 405` (counter-example — POST to a known path); `should complete the edge-HIT mission only on a trace edge HIT, not an origin cache HIT` (stage 6: run `example.com/about` till cache HIT then `cd.example.com/about` MISS then HIT, per 6b flow); `should prefill the mini-browser from a mission that carries a URL (no auto-send)`; `should clear verified missions on a stage switch`. Cover at least one crowd-tick stability pin implicitly (run the crowd between missions).
- Manifests: `slices.yaml` (PANEL e2e gains `e2e/missions.spec.js`; ground glob/dedup rules) + `storymap.yaml` (story under the row owning the teaching drawer; carry the unit + e2e titles, names identical; ground rows first).
