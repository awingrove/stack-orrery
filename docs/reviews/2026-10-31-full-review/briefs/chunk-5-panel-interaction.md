# Chunk 5 — Panel interaction — Context Brief

## Layer map

- Bootstrap: `panel.js` is the composition root — imports and side-effect-mounts rail, teaching-drawer, fault-console, fs-editor, compare, journey-log (via imports + direct calls); owns engine, stage state, URL state, trace stepping. It passes `getEngine`/`rerender` accessors (not engine refs) into fault-console and fs-editor.
- Per-snapshot pipeline: `render.js` calls `renderFilesystems(snapshot)` (fs-editor), `updateMissions(snapshot)` (missions-view), `updateFaultConsole(snapshot)` (fault-console) at render.js:216/253/254. panel.js only calls the `init*` forms of fault-console/fs-editor.
- Dependency edges: compare.js ← model.js (nextCompareSlots/alignCompareRows); journey-log.js ← model.js (orderJourneyEntries); missions-view.js ← missions.js + rail.js; fault-console.js ← rail.js; teaching-drawer.js ← teaching.js + rail.js; rail.js depends on nothing; inspector-source.js ← inspector-source-stage6.js; fs-editor.js imports nothing.

No module removes its listeners on stage switch; singleton `_init*` mounts run once.

## fs-editor facts

- Reads from `snapshot.servers[i].files` (Object.entries of the sim's fs Map, insertion order "/","/about" — fs-editor.js:113); `container.dataset.serverAddress = server.address` (fs-editor.js:148); commit calls `getEngine().setWebFile(serverAddress, path, value)` then `rerender(getEngine().snapshot())` (fs-editor.js:171-173). It is a sim-server write, not a network PUT/GET — no HTTP path: the editor goes through the engine accessor directly; the "PUT realism" layer does not exist in this file.
- Route-id parity: server-1 rows keep `id="route-*"` + `data-file="route-*"`, server-2 keeps `data-file-2` (fs-editor.js:46-51,78-83) so `renderRoutes()` highlight parity holds; `routeIdFor` mirrors sim's webserver.js rule (fs-editor.js:28-30).
- Edit lifecycle guards: one edit per card (`editingPath` keyed by listId :36-37); live editor row preserved across re-renders (:113-137); commit disabled while unchanged/empty (delegated `input` :190-197); Enter→commit (no-op when disabled), Escape→close from EXISTING snapshot (:162,199-208). Crowd ticks re-render both cards every snapshot via render.js:216.
- `lastSnapshot` module state means startEdit/closeEdit act on the last-seen snapshot, not a fresh one.
